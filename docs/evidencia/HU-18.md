## Decisiones y fuentes

| Pregunta / hecho | Decisión y evidencia |
|---|---|
| Q1 — roles | Solo roles existentes: coordinador ve sus áreas con perfiles profesionales activos; sysadmin puede ver todas o seleccionar una. El selector conserva todas las áreas permitidas tras filtrar. Policy: `app/Policies/IndicadorPolicy.php`; decisiones #1332. No se crea `directivo`. |
| Q2 — catálogo | Doce indicadores agregados; sin cortes por paciente ni profesional. `app/Enums/TipoIndicador.php`, fórmulas en `docs/indicadores.md`; decisión #1335. |
| Q3 — privacidad | Umbral 5 con supresión primaria/complementaria; rate oculto si cualquiera de sus conteos base es <5. `IndicadorService::suprimirCeldas()`; decisión #1333. |
| Q4 — período | 30 días por defecto, máximo 366 días calendario inclusivos. Las fechas locales se traducen a UTC con offset explícito para PostgreSQL. `IndicadoresRequest`/`IndicadorService`; decisión #1334. |
| Q5 — gráficos | Tablas accesibles y barras SVG inline, sin dependencia nueva. UI implementada en `resources/js/Pages/Indicadores/Index.vue`; usa layouts y `FieldTooltip` existentes según `ESTANDARES.md` §5/§5.1. |
| Q6 — `AreaScope` | No se hidratan modelos ni se llama `withoutGlobalScope`; Query Builder selecciona columnas explícitas y aplica la lista de áreas autorizadas. Cumple `ESTANDARES.md` §4.44. |
| Tipo de `areas.id` | Entero sin signo en el esquema real; el filtro valida entero, aunque B.5 muestra UUID como ejemplo. No se altera el esquema. |
| Fechas fuente | `consultas.fecha_consulta`, `citas.fecha_hora`, `expedientes.fecha_derivacion/fecha_cierre` (con `created_at` para derivación legado nula), `alertas_preventivas.generada_en` y `seguimientos_preventivos.created_at`. |
| Índices | Las citas ya tienen índice por `fecha_hora` y alertas por `(area_id, generada_en)`. La migración HU-18 añade seis índices no únicos con predicados `deleted_at` donde aplica; no hay nuevo constraint único ni chequeo de colisiones necesario. |

El SQL usa cinco agregados fijos (consultas/pacientes, expedientes, citas, alertas y seguimientos) cuando se solicitan todos los indicadores; solo ejecuta los grupos de fuente necesarios para los indicadores elegidos. El test E11 confirma que el número no crece al añadir áreas.

La auditoría de lecturas registra actor, acción, objeto agregado, filtros, fecha e IP, sin valores calculados ni PHI. E08 verifica el Resource completo y el registro crudo de `audits`.

### Fuente única de verdad para respuestas HTTP

| Código | Capa | Caso HU-18 |
|---|---|---|
| 302/401 | Middleware `auth` | Invitado: redirección a login para HTML; 401 en request JSON. |
| 403 | `IndicadoresRequest::authorize()` + `IndicadorPolicy::ver()` | Rol sin permiso o coordinador solicita un área fuera de su alcance. |
| 422 | `IndicadoresRequest` | Fechas/formato/rango, área inválida para sysadmin, indicador vacío/desconocido/duplicado. |
| 404 | Route resolver | No hay binding de un recurso HU-18; no aplica al `GET /indicadores`. |
| 409 | No aplica | Endpoint solo lectura; no hay transición ni escritura concurrente de dominio. |

La lectura auditada solo ocurre después de validación/autorización exitosa; los rechazos no crean un resultado ni ejecutan el servicio de agregación.
