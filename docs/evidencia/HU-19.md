## Auditoría de alcance y errores

- Stack real: PHP 8.4, Laravel 13.12.0, Inertia Laravel 3.1.0 / Vue adapter 3.3.0, Pest 4.7.0; no se agregan dependencias ni migraciones.
- Sin bypass de `AreaScope`: ReporteService delega a HU18 `IndicadorService`; la fuente de áreas autorizadas sigue en `IndicadorPolicy` y no se hidratan modelos fuente.
- Códigos: invitado 302/401 por middleware `auth`; rol o área ajena 403 por Request/Policies; filtros faltantes/inválidos 422 por `ReporteGenerarRequest`; 404 no aplica (sin binding de recurso); 409 no aplica (GET de solo lectura más auditoría de generación).
- Frontend: `Reportes/Index.vue`, ambos layouts con enlace `can.reportes`; el prop `puede_todas_areas` controla la opción “todas”. Usa `useForm`/GET, estado de carga, errores 422, resumen enfocado, estado vacío y tablas con caption/scope, siguiendo `ESTANDARES.md` §5/§5.1.
- Compliance: V4 Policy/área (E06/E08), V6 sin PII en props/auditoría (E10), auditoría de generación con filtros/actor/IP sin resultados (E10), DDL/DML segregados sin nueva tabla.

| Código | Fuente única de verdad |
|---|---|
| 302/401 | Middleware `auth` (HTML redirige a login; JSON devuelve 401). |
| 403 | `ReporteGenerarRequest` + `ReportePolicy`/`IndicadorPolicy` (rol o área fuera de alcance). |
| 422 | `ReporteGenerarRequest` (período, área requerida, indicadores y máximo de dos agrupaciones). |
| 404 | No hay binding de reporte; la ruta GET no referencia un recurso persistido. |
| 409 | No aplica: el contenido se genera bajo demanda y no hay estado de reporte persistido que entre en conflicto; solo queda el evento de auditoría de parámetros. |

Los dos primeros intentos full-suite se solaparon accidentalmente contra la misma base PostgreSQL `testing` y produjeron deadlocks de inserción en `roles` y conflictos de esquema entre tests de migración. Esas corridas no se usan como resultado de HU-19. `phpunit.xml` fija `DB_DATABASE=testing`; tras serializar los comandos, dos corridas completas dieron el resultado idéntico de arriba, sin deadlocks. No se cambió código ni tests heredados para ocultar el problema.

Los greps en HU-19 no encuentran validación inline nueva, `$this->assert`, rol en Vue, `v-html`, llamadas de depuración ni `withoutGlobalScope` nuevo. Los hits existentes pertenecen a controladores/páginas anteriores de citas, pacientes y búsqueda segura; no se modificaron.
